# Проверка совместимости задачи и профиля

Проверка добавлена после аудита 8 сентября: семантическая близость пропускала
Senior/Staff-вакансии для новичка, Lead QA для SMM и обязательный английский B2
для человека, указавшего только русский.

После отбора не более `matching_retrieval_top_k` кандидатов выполняется проверка
исходного объявления вместе с профилем и портфолио. Она не меняет числовой рейтинг.
Проверяется сама оплачиваемая задача, профессия, обязательные требования,
регулярность работы и ограничения пользователя. Бюджет без суммы, отсутствие
коммерческого портфолио и отдельный осваиваемый инструмент не являются причинами
отказа. Для неоднозначных условий остаётся вариант с компромиссом.

Отказ модели применяется при уверенности не ниже 0.8 и проверенных дословных
фрагментах из объявления и профиля. Явное требование повторяющейся работы,
подтверждённое цитатой с регулярностью и выключенной настройкой part_time,
проверяется отдельно от общей оценки соответствия навыков. Короткие указания
English/английский B2, Fluent English и «знать английский» проверяются до LLM;
необязательный английский не становится жёстким требованием.

Результаты сохраняются в `compatibility_cache` по пользователю и объявлению.
Хэш включает полный исходный текст, профиль, портфолио, модель, провайдера и версию
правил. Изменение любого входа инвалидирует результат. Неуверенный ответ `unknown`,
ошибка API и неподтверждённая цитата не сохраняются как отказ.

Одновременно выполняются не более двух LLM-запросов на экземпляр сервиса;
пакет по умолчанию содержит 8 объявлений. Общий предел ожидания — 45 секунд.
Успешные пакеты сохраняются даже при тайм-ауте остальных. Ошибочный структурный
ответ или неподтверждённые цитаты допускают один повтор; размер повреждённого
пакета при повторе уменьшается. Повторные HTTP-ошибки не создают цикл запросов.

При недоступности проверки сохраняется прежний подбор, а число непроверенных
кандидатов и сбой отражаются в логах. Это режим деградации, а не подтверждение
пригодности. При отсутствии явно подходящих заказов сервис не выдумывает их.

## Выкладка и откат

Миграция `0011_compatibility_cache` добавляет только производный кэш, с внешними
ключами на пользователя и объявление и каскадным удалением. Старый код не использует
эту таблицу. Git-откат не восстанавливает пересчитанные рекомендации. Перед
выкладкой сохраняется БД; история откликов при пересчёте остаётся неизменной.
Ключи провайдера и действующий Timeweb LLM не меняются этой доработкой.

## Проверка

Тесты покрывают сохранение и инвалидацию кэша, дословность обеих цитат, невалидные
ответы, недоступность API, слишком длинный элемент ответа, сохранение успешных
пакетов при тайм-ауте, регулярную работу при совпавших навыках и блокировку
несовместимой рекомендации при обычном поступлении заказа. На трёх синтетических
профилях выполняется отдельный прогон по сохранённым реальным объявлениям;
синтетические пользователи не создаются в production.
